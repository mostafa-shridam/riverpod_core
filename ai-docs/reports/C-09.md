# C-09 — design_system widgets: buttons and text inputs

Worker A · branch `worker-a` · worktree `../riverpod_core-a`

## What changed
- **Buttons** (`lib/design_system/widgets/buttons/`)
  - `AppButton`: variants primary, secondary, tonal, outlined, text, destructive; sizes sm/md/lg (heights 40/48/56 from tokens); `isLoading` keeps the label width (the label is kept, hidden, under a spinner) and blocks taps; leading and trailing icons (start/end, so they mirror in RTL); `fullWidth`; disabled when `onPressed` is null. No haptics.
  - `AppIconButton`: filled, tonal, outlined, standard; sizes shared with `AppButton`; `tooltip` is required (it is the accessible name); `badge` slot at the top-end corner.
  - `AppFab`: plain or extended (`label`); `tooltip` required; no hero tag clash.
- **Inputs** (`lib/design_system/widgets/inputs/`)
  - `AppTextField`: label, hint, helper, error (server error text), prefix/suffix (icons or text), `validator`, multiline (`minLines`/`maxLines`), counter via `maxLength`, focus/error/disabled/read-only states, directional padding.
  - `AppPasswordField`: hidden by default, show/hide toggle with localized tooltips.
  - `AppSearchField`: clear button (shown when there is text), `onChanged` debounced by the `searchDebounce` token (300 ms), clearing fires at once, the pending timer is cancelled on dispose.
  - `AppOtpField`: `length` boxes, one hidden text field behind them; digits only; a paste keeps only the digits, up to `length`; `onChanged` and `onCompleted` (fires once when full); error text in the error color; each box has a localized accessible label.
  - `AppPhoneField`: digits only, phone keyboard, phone icon, no country picker.
  - `localizedValidator(rule)` turns a core rule into a Form validator that returns localized text.
- **Core** `lib/core/utils/validators.dart`: pure rules returning `ValidationError?` (enum: required, invalidEmail, passwordTooShort, invalidPhone, phoneTooShort). No UI text in core. Replaces `validateEmail/validatePassword/validateRequired/validatePhone`, which had no importers.
- **Strings** (D-023): `buttons_strings.dart` and `inputs_strings.dart` hold the key constants. Keys were added to both JSON files under `ds_buttons` and `ds_inputs`, appended at the end.
- **Tokens** (approved by the Lead): new `lib/design_system/tokens/app_sizes.dart` (`AppSizes`, a field of `AppTokens` with copyWith); `searchDebounce` in `app_durations.dart`.
- **Deleted**: `lib/core/widgets/app_button.dart` (no importers). `custom_button.dart` and `my_text_filed.dart` were already deleted in C-05.
- **DESIGN_SYSTEM.md**: one row for sizes in the Tokens section.
- **TASKS.md**: C-09 status set to REVIEW.

## Decisions made
- **Validators return an enum** (approved): core stays free of UI text. `design_system` maps it to `ds_inputs.errors.*`.
- **OTP `Directionality(textDirection: TextDirection.ltr)`** (approved; to be recorded as D-025 by the Lead): the only hard-coded direction in the library. Digits always read left to right. It is limited to `AppOtpField`.
- **Button colors** come from the M3 `ColorScheme` by variant, with `null` falling back to M3 disabled colors. No alpha values are hard-coded.
- **Search debounce and clearing**: clearing fires `onChanged('')` at once, without waiting for the debounce.
- **Phone field**: digits only; no country code handling (the app adds it).
- **Validators tests** live in `test/core/utils/` (outside the task's test list) and the message mapping is tested in the inputs tests. This is a small extension of the Files list; the Lead can say if it should move.
- **Icon-only buttons** require a tooltip (required parameter), which is their accessible name.
