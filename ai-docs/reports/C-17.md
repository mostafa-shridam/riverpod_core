# C-17 — Auth: session, login/register pages, logout resets everything

Worker A · branch `worker-a` · worktree `../riverpod_core-a`

## What changed
- **SessionController** (`lib/core/auth/session_controller.dart`, keepAlive): replaces the C-11 stub. `SessionStatus { unknown, signedOut, signedIn }` is the state, so guards keep reading the status enum. The current user is a separate keepAlive provider (`SessionUser`), so the router does not rebuild on user changes.
  - `restore()` reads the access token from `SecureStorage` and the cached user; no token means `signedOut`, a token with a valid user means `signedIn`, and a corrupt user record means `signedOut`.
  - `signIn(tokens, user)` stores both and sets `signedIn`.
  - Implements `AccessTokenRefresher`, and `accessTokenRefresherProvider` (C-07) now defaults to it. Refresh posts `AuthEndpoints.refresh` through the refresh-only Dio, stores the new tokens, and the single-flight refresher in the network layer does the rest.
  - Listens to `SessionEvents.expired` and ends the session locally (no remote call).
  - `logout({remoteLogout})` is the ONE logout function: best-effort remote logout first (a failure is logged as a warning and does not block), then `clearUserData` (secure storage, cache DB, user-scoped prefs), analytics `setUserId(null)` + `reset()`, bump of `sessionEpochProvider`, then `signedOut`. `signOut()` delegates to it.
- **Invalidation mechanism (documented choice)**: `SessionEpoch` (`lib/core/auth/session_epoch.dart`, keepAlive) is an int counter. User-scoped providers `ref.watch(sessionEpochProvider)`, so bumping it rebuilds them and drops cached user data. Chosen over a root `ProviderScope` key because it keeps the app-level providers (config, storage, Dio) alive across logout.
- **Endpoints and mock switch** (`lib/core/auth/auth_endpoints.dart`): all five endpoints in one file (`/auth/login`, `/auth/register`, `/auth/refresh`, `/auth/logout`, `/auth/forgot-password`). `const bool authUseMockSource = true` selects `MockAuthSource` (in-memory, 400 ms delay) versus `HttpAuthRemoteSource`, the same switch shape as the videos feature (D-028). Set it to `false` once the endpoints exist.
- **Auth tokens and user**: `lib/core/auth/auth_tokens.dart` (freezed `AuthTokens`); `lib/shared/models/auth_user.dart` (freezed `AuthUser`, in `shared` because `core` needs it).
- **Feature**: `lib/features/auth/data/` (`auth_remote_source.dart`, `auth_mock_source.dart`, `auth_repository.dart` with errors mapped through `mapError`, models `auth_requests.dart` and `auth_session.dart`), `lib/features/auth/providers/{login,register,forgot_password}_controller.dart`, pages `login_page.dart` (replaces the temporary placeholder), `register_page.dart`, `forgot_password_page.dart`, and `presentation/widgets/auth_layout.dart`.
  - Each page has `static const routeName` and a `ValueKey('<page>-page')` root. Pages use only design-system widgets: `AppTextField`, `AppPasswordField`, `AppButton` with `isLoading`, `showAppSnackbar` for non-field errors, and field errors from `ValidationException.firstMessageFor`.
  - Validation uses `Validators` from `core/utils` through `localizedValidator`.
  - Labels use `LocaleKeys.auth_*.tr()`. No literal keys in auth code.
- **Router** (`lib/core/router/routes.dart`, minimal): adds `RegisterRoute` and `ForgotPasswordRoute`. `app_redirect.dart`: the signed-out allowed set includes login, register and forgot-password; signed-in excludes them.
- **More page** (`lib/features/more/presentation/pages/more_page.dart`): logout button calls `sessionControllerProvider.notifier.logout(remoteLogout: ...)`.
- **Translations**: top-level `auth` object appended to `assets/translations/en.json` and `ar.json`.
- **Generated code**: `lib/generated/{codegen_loader,locale_keys}.g.dart` regenerated (D-037), with the easy_localization commands, `dart format`, and build_runner. Freezed and json files regenerated for the new models.
- **Splash** (`lib/core/startup/splash_page.dart`): not touched; it calls `restore()` as before.

## Decisions
- Logout is a method on `SessionController`, not a separate `lib/core/auth/logout.dart`. The task said "logout is one function"; one method keeps the orchestration in one place.
- Model files are `auth_requests.dart` and `auth_session.dart`, not `login_request`/`register_request`; one freezed file per group.
- `AuthUser` lives in `lib/shared/models/` because `core` needs it and `core` must not import `features`.
- Golden tests use the test font, which has no Arabic glyphs, so the Arabic goldens show placeholder boxes. The goldens are regression baselines; they will not show real Arabic glyphs until a font is loaded in tests.
- The network-error message in tests uses the real `en.json` copy (`No internet connection. Check your network and try again.`).
