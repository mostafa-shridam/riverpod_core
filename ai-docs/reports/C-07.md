# C-07 — Dio client, interceptors, error-mapping wiring

Worker A · branch `worker-a` · worktree `../riverpod_core-a`

## What changed
- **`dioProvider`** (keepAlive, `lib/core/network/dio_client.dart`): one `Dio` from `AppConfig` (base URL, connect and receive timeouts). Interceptors in NETWORKING.md order: idempotency, auth, refresh, retry/backoff, logging (only at log level debug), error mapping (always last).
- **`refreshDioProvider`**: second client with no auth and no refresh interceptor, for the refresh call only.
- **`httpClientAdapterProvider`**: the transport (`IOHttpClientAdapter`). Tests override it with `FakeHttpAdapter`.
- **Idempotency** (`interceptors/idempotency_interceptor.dart`): adds a uuid v4 `Idempotency-Key` to POST/PUT/PATCH/DELETE unless the caller set one.
- **Auth** (`interceptors/auth_interceptor.dart`): reads the access token from `SecureStorage` and sends `Authorization: Bearer`; skipped when `extra['skipAuth'] == true`.
- **Refresh** (`interceptors/refresh_token_interceptor.dart`): on 401, renews once and replays. Concurrent 401s share one refresh (`SingleFlightRefresher`). A 401 sent with an older token is replayed with the stored token without a new refresh. If the refresh fails: tokens are deleted, `SessionEvents` is raised, and the original 401 goes on (maps to `UnauthorizedException`).
- **Retry** (`interceptors/retry_backoff_interceptor.dart`): only idempotent requests (GET, HEAD, PUT, DELETE, or any request with an `Idempotency-Key`); only connection and timeout errors, socket failures reported as unknown, and 429/502/503/504. Max 3 attempts total. Delay `500 ms × 2^(n-1) + jitter`; `Retry-After` (seconds) is honored when present. Other 4xx are never retried.
- **Logging** (`interceptors/logging_interceptor.dart`): one line per request with method, path, status or error type, and duration. Allow-list: headers, query strings and bodies are never read.
- **Error mapping** (`interceptors/error_mapping_interceptor.dart`): calls `mapError` from `core/errors` (no mapping logic here) and rethrows `DioException(error: AppException)`.
- **Token refresher** (`token_refresher.dart`): `AccessTokenRefresher` interface; `SingleFlightRefresher`; `UnconfiguredRefresher` (default, always fails until C-17); `accessTokenRefresherProvider`. `dioProvider` wraps whatever is bound in `SingleFlightRefresher`.
- **Session signal** (`session_events.dart`): `SessionEvents` with a broadcast `expired` stream, `notifyExpired()` (emits once per expiry), `markSignedIn()` (re-arms). `sessionEventsProvider` is keepAlive. C-17 consumes it.
- **Deleted**: `lib/core/remote_services/**` (`api_service`, `api_result`, `api_exceptions`, `dio_client`) and `lib/core/error_handler/**` (`error_handler`, `failure_messages`). They had no importers outside themselves.
- **TASKS.md**: C-07 status set to REVIEW.
- **Generated**: `dio_client.g.dart`, `session_events.g.dart`, `token_refresher.g.dart`, committed next to their sources.

## Decisions made
- **Single-flight is applied in `dioProvider`**, not only in the bound refresher. Overriding `accessTokenRefresherProvider` (as C-17 will) therefore keeps the single-flight guarantee.
- **Session expiry** is raised only from the refresh path, and only once per expiry (`markSignedIn` re-arms it).
- **Retry scope**: a write is retried only because it carries an `Idempotency-Key`, so a POST without one is never retried. Socket failures reported by Dio as `unknown` are treated as connection errors.
- **Send timeout**: `AppConfig` has no send timeout, so sends use the receive timeout. NETWORKING.md's 30 s default and the config value agree for the current defaults.
- **Logging sink** is `dart:developer` for now. C-08 replaces it with the app logger.
- **Refresh endpoint is not defined here.** `refreshAccessToken()` is C-17's job; until then 401s end the session.
