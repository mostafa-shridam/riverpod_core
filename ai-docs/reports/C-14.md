## Behaviour of the notifier
- `loadMore()`: ignored while loading, while another load-more runs, or when there is no next page. A failed page sets `pageError`, keeps the items and the failed request, so calling `loadMore()` again retries that page. Items are de-duplicated by `idOf`.
- `refresh()`: the items stay while it reloads. If it fails with items on screen, the items stay and `pageError` is set. If it fails with no items, the state is an `AsyncError` with an `AppException`.
- `retry()`: calls `refresh()` if the last failure was a refresh, otherwise `loadMore()`.
- Results that arrive after a newer refresh or after dispose are dropped. Dart futures cannot be cancelled, so the fetch itself still completes in the background.
- Errors are mapped once with `mapError`. Unknown errors become `UnknownException`.

## Decisions made or needed
- **Test providers are hand-written** (`AsyncNotifierProvider`). `build.yaml` restricts code generation to `lib/**`, and changing it needs a DECISION, so the notifier tests do not use `@riverpod`. The production pattern, a `@riverpod` class extending `PaginatedNotifier`, was checked with a temporary probe in `lib/` (generated and analyzed clean); the probe files are removed.
- **Riverpod retries a failing `build` by default.** The notifier tests use a container with `retry: (_, _) => null`. The app's retry policy is not decided here: the Lead should choose whether a failed first load in the app should retry automatically.
- **Location:** the Files list says `widgets/lists/`, but DESIGN_SYSTEM.md lists `PaginatedListView` under `async/`. I followed TASKS.md. DESIGN_SYSTEM.md needs one line fixed, or the Lead should confirm the folder.
- **Error text is passed in as a string.** The design system must not import `core/errors` (layering rule), so the caller maps `pageError` with `errorMessageKey` and passes `pageErrorText`.
- **Retry key:** `ds_lists.retry` (D-023) rather than reusing `errors.retry`.
- **`refresh()` failure with items:** the items stay and `pageError` is set. The retry for that case is `refresh()`, through `retry()`.
