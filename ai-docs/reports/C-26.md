## What changed
- **Video player seam** (accepted extra files, approved by the Lead):
  - `lib/core/design_system/widgets/media/app_video_backend.dart`: keepAlive provider `videoBackendFactoryProvider` (default `createVideoPlayerBackend`).
  - `lib/features/videos/presentation/pages/video_detail_page.dart`: `backendFactory` is nullable; the page reads the provider when none is passed.
  - Why: the detail page built the real `video_player`, so the flow could not run without a network and a codec. The task's "provider override" did not exist.
  - Test: `test/core/design_system/widgets/media/video_backend_factory_test.dart` (the default is `createVideoPlayerBackend`; an override replaces the backend every player gets).
- **Integration tests** (`integration_test/`):
  - `app_flow_test.dart`: cold start, onboarding, sign-in with wrong then right credentials, home, videos list, first video, play surface, favorite, More → About, logout back to login. Starts the real app through `bootstrap` with the seams in `helpers/flow_setup.dart`.
  - `screens_test.dart`: walks splash, onboarding, login, home, videos list, and the showcase in English and Arabic, light and dark. Captures only under `flutter drive` with `CAPTURE_SCREENS=true`.
  - `screens_driver.dart`: the `flutter drive` driver. It writes each screenshot from the response data to `$SCREENS_DIR/<name>.png`.
  - `helpers/flow_setup.dart`: `startApp`, fresh storage, the `flowEnv` env (no real values, no network), `FlowVideoBackend` (fake player with a fixed surface), mock remote config, in-memory secure storage (the test-helper `FakeSecureStorage`).
  - `helpers/pump_until.dart`: `pumpUntilFound` and `tapWhenFound` poll for a finder. `pumpAndSettle` is not used because spinners never settle.
- **`pubspec.yaml`**: `integration_test` as an SDK dev dependency only (ships with Flutter; no new package, no version pin needed).
- **`tool/smoke.sh`**: clean-clone smoke. Copies `HEAD` with `git archive` into a temp dir; fails if Firebase or keystore files are present; copies only `env/*.env.example`; runs pub get, codegen, format, analyze, `flutter test`, `flutter build apk --debug`, `flutter build ios --no-codesign --debug`, and the flow test on a booted or newly booted simulator (shut down afterwards if it booted it). Exits non-zero on the first failure. It never touches the working tree.
- **`.github/workflows/ci.yml`**: new job `integration-ios` (macOS, iPhone simulator, flow test), triggered by `workflow_dispatch` and a nightly `schedule`. It is not required for PRs. The `test` job is limited to push and pull_request so the scheduled run does not repeat the whole gate.
- **`ai-docs/TESTING.md`**: integration section (seams, the no-timer rule, screenshots, smoke script, CI job).
