# C-38 — AppVideoPlayer (Worker H)

## What changed
`AppVideoPlayer` in `core/design_system/widgets/media/`, built on `video_player` (D-027) behind an injectable playback backend, so tests never need a platform channel.

- `AppVideoPlayer(source | controller, autoPlay, looping, aspectRatio, placeholder, onEnded, labels, backendFactory)`. Rounded (`radius.lg`), scrim-colored letterbox, 16:9 until the video reports its ratio. Without `controller` it owns and disposes one; with an external one (Riverpod provider) it never disposes it. Pauses on `paused`/`hidden` app lifecycle (does not auto-resume).
- `AppVideoController extends ValueNotifier<AppVideoState>`: status (initializing, ready, playing, paused, buffering, ended, error), position, duration, buffered, volume, speed, aspectRatio, errorMessage. `initialize/retry/play/pause/togglePlay/seekTo (clamped)/seekBy/setSpeed/setMuted/toggleMute/dispose`. `onEnded` fires once per end, never when looping. Play from ended restarts at 0. Dispose is safe during initialization.
- `AppVideoSource.network/asset/file` (sealed, value equality), `AppVideoBackend` interface + `AppVideoBackendFactory`; default `createVideoPlayerBackend` wraps `VideoPlayerController`.
- Controls: gradient scrim (top and bottom), big filled play/pause/replay button, seek bar (custom painter: track, buffered segment, played segment, thumb that grows while dragging, tap + drag), elapsed/total time (locale digits via `NumberFormat`), mute, speed popup (0.5/1/1.5/2), fullscreen toggle, double-tap seek +-10 s with a flash badge, auto-hide after 3 s while playing, fade with `durations.normal`/`standardCurve`, buffering spinner, error panel with retry. The gesture layer sits UNDER the chrome, so button taps are not delayed by the double-tap timeout.
- Fullscreen: fade route on the root navigator, landscape orientations + `immersiveSticky`, restored in `finally` (orientations released, `edgeToEdge`).
- Chrome is always drawn with `buildDarkTheme()` (white on scrim, like every media player), independent of the app mode. All sizes/spacing/radius/duration from tokens.
- RTL: seek bar is forced LTR with a comment (timeline is not text; double-tap halves are physical for the same reason); the controls row and the time text are directional (verified by test: fullscreen button moves to the physical left in ar).
- Strings: `media_strings.dart` keys + optional `AppVideoLabels` override for every label; `ds_media` appended at the end of `ar.json` and `en.json` (14 keys). `lib/generated/*.g.dart` NOT regenerated (D-023), the Lead regenerates after merge.

## Decisions made / notes
- `appVideoSeekStep` (10 s), `appVideoAutoHideDelay` (3 s) and `appVideoSpeeds` are named constants in `app_video_controller.dart`: they are behaviour values fixed by the task, not visual tokens, and no token fits. Alpha values of scrims (0.25/0.5/0.7) are literals on `scheme.scrim`.
- Tests import `../display/ds_test_harness.dart` (owned by C-34) for `pumpDs`/`goldenModes`; if that file moves, the media tests need the import updated.
- Import ordering lint wants `riverpod_core` before `video_player` in one file.
