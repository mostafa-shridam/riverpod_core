# C-20 — Notifications: FCM + local, best practice, complete

Worker S · branch `worker-s`

## What changed
- Replaced the singleton notification code (`LocalNotificationsService.instance`, `FirebaseMessagingService.instance`, `NotificationInitializer.instance`, `DeepLinkHelper.instance`) with a provider-based system under `lib/core/notifications/`. Full description: `ai-docs/NOTIFICATIONS.md`.
- **Facade**: `NotificationService` (`notificationServiceProvider`): `initialize()` (never throws, never prompts), permission flow, master/channel switches, `onSignedIn`/`onLogout`, `silentMessages`, `actions`, `syncChannelLabels()`. `notificationLogoutProvider` is the hook the auth feature calls before `clearUserData`.
- **Plugins behind backends** (all overridable providers, fakes in `test/helpers/fake_notification_backends.dart`): `LocalNotificationBackend` (flutter_local_notifications), `PushBackend` (firebase_messaging), `NotificationPermissionBackend` (permission_handler), `TimezoneBackend` (flutter_native_timezone_latest), `DeviceInfoSource` (device_info_plus).
- **Firebase optional**: `FirebasePushBackend.initialize()` returns false when `Firebase.initializeApp` fails; `PushService` logs once ("Push is disabled"), `pushAvailableProvider` = false, local notifications and the rest keep working.
- **No Firestore**: the old `saveUserDeviceData` is gone (`lib/core/services/info_service.dart` deleted). Token registration goes through `PushTokenRegistrar` (default `NoopPushTokenRegistrar`; `DioPushTokenRegistrar` example with `pushTokenEndpoint` in one file, not wired).
- **Push**: token + refresh stream, register on sign-in / refresh, unregister + `deleteToken` on logout, topic helpers, foreground messages (Android: local notification on the right channel; iOS: system presentation, toggled with the master switch), top-level `@pragma('vm:entry-point') firebaseMessagingBackgroundHandler` (no Riverpod, never throws), `getInitialMessage`, `onMessageOpenedApp`, data-only (`silentMessages`) and notification+data messages, de-duplication by message id (separate dedupers for shown and opened).
- **Local**: channel table in ONE file (`general`, `high_priority`, `silent`, `reminders`, two groups; id, name, description, importance, sound, vibration, badge, group), monochrome `ic_notification` drawable, accent color `brandSeedColor`, iOS category with reply + mark-read actions, `show`, `schedule`, `scheduleDaily`, `scheduleWeekly` (exact only when allowed, else inexact; returns `ScheduleResult`), `cancel`, `cancelAll`, `pending`, big text / big picture / group summary, `NotificationBadge`, time zone init.
- **Routing**: `NotificationRouter` turns every tap (push opened/initial, local tap/launch) into `(type, id)`, resolves it through `routeForDeepLink`, falls back to an http(s) `url`, ignores unknown types, queues taps until the app router is attached AND the user is signed in, then replays in order. `app_router.dart` attaches with `router.go`.
- **Settings**: `NotificationSettings` + `NotificationSettingsController` (master = `PrefsStorage.notificationsEnabled`; channel switches = list of disabled ids at `user.notifications.disabledChannels`), `notificationPermissionStateProvider`, `openSystemSettings()`.
- **Device**: `lib/core/device/` (`DeviceInfo`, source, `deviceInfoProvider`); a random per-install id (device scope, survives logout) instead of hardware ids.
- **Platform**: AndroidManifest (receivers for scheduled/boot/action, default channel id and icon meta-data; `USE_EXACT_ALARM` removed on purpose), `ic_notification.xml`, iOS `Info.plist` (`UIBackgroundModes` = remote-notification), `Runner.entitlements` (aps-environment development) referenced from `project.pbxproj` in all three Runner configs, `AppDelegate.swift` sets the `UNUserNotificationCenter` delegate.
- **Strings**: top-level `notifications` in both JSONs (channel/group names and descriptions, iOS action titles, group summary); `LocaleKeys` regenerated and committed.
- **Deleted**: `lib/core/helper/deep_link_helper.dart`, `lib/core/helper/help_functions.dart`, `lib/core/services/helper.dart` (nothing imported them after the change; verified by grep), `lib/core/services/info_service.dart`, the three old notification files.

## Decisions made or needed
- **Needed (Lead): `AppPermission.notifications`.** The task says to use the existing `PermissionService` and rationale dialog, but `AppPermission` only has camera/photos/microphone and the files that would change (`lib/core/permissions/app_permission.dart`, `permission_service.dart`, `design_system/.../permission_rationale_dialog.dart`, and the `ds_permissions` keys) are outside the C-20 Files list. I did not touch them. Instead `NotificationPermissionFlow` mirrors `PermissionService.ensure` with its own backend and a `NotificationRationalePresenter` (provider `notificationRationalePresenterProvider`, null by default). Follow-up (5 small edits): add the enum value + `ph.Permission.notification` arm + dialog icon + `notificationsTitle/notificationsMessage` keys, then delete `NotificationPermissionFlow`'s presenter in favour of `PermissionService`.
- Token API: `getToken`/`onTokenRefresh`/`deleteToken` are deprecated in firebase_messaging 17 (replacement `register()`/`onRegistered` returns a Firebase Installation ID, not the FCM token). I kept them behind `PushBackend` with `ignore: deprecated_member_use` in one file. Switch there if the backend wants FIDs.
- Per-channel flags are stored as ONE string list (`user.notifications.disabledChannels`) through the existing `getStringList/setStringList` slot, because `PrefsStorage` (C-41 is moving it to Hive) is not in my Files list and has no generic bool accessor.
- A tap needs the user signed in; urls are queued too (same readiness rule). Unauthenticated deep links are not kept across the login screen beyond the queue (max 5, in memory).
- `USE_EXACT_ALARM` removed from the manifest: Play only allows it for alarm/clock apps; `SCHEDULE_EXACT_ALARM` stays.
- iOS foreground pushes: the system presents them (no local duplicate); Android shows them through a local notification.
- `ios/Runner.xcodeproj/project.pbxproj` and `AppDelegate.swift` were edited although only `Runner.entitlements` is named: an entitlements file that the project does not reference is inert, and the plugin needs the delegate line. Both are platform files (the brief allowed platform file updates).
- No new packages. flutter_local_notifications 22.3.2, firebase_messaging 17.0.0, timezone 0.11.2, flutter_native_timezone_latest 1.0.0, permission_handler 13.0.2 needed these API adaptations: `initialize(settings:)`, named `show/zonedSchedule/cancel` parameters, no `uiLocalNotificationDateInterpretation`, `AuthorizationStatus.deniedPermanently`.
