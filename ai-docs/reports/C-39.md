## Flavor gating (exactly how)
- Routes are always registered (generated `$appRoutes`), but both `GoRouteData.redirect` overrides call `_devOnlyRedirect`, which reads `appConfigProvider.flavor` from the `ProviderScope` and redirects to `/home` when the flavor is `prod`. A deep link therefore cannot open the feature in prod.
- Entry points hidden in prod: the home tile (`flavor != prod`) and the simulate menu (`videosSimulationEnabled`: flavor != prod AND mock source active). The custom-link button lives on the list page, which is unreachable in prod.
- I did not edit `app_router.dart` (not in my Files list), hence redirect instead of conditional route registration.

## Decisions made / notes
- `Riverpod` keeps previous data inside `AsyncLoading`/`AsyncError` assigned to `state`, so a "from scratch" reload cannot be expressed through state alone. `VideosController.dropsPreviousData` (true from `reload()` until the next success or `refresh()`) lets the page show plain loading/error after a simulate switch. `refresh()` uses `invalidateSelf()` and keeps data (refreshing/stale).
- Tests build containers with `retry: (_, _) => null` (D-032); the shared `createContainer` helper does not set it.
- Duration badge uses `AppBadge` with a formatter (it is a pill in the error color; a neutral variant would need a design_system task).
- Offline simulation: the list page overrides `connectivityProvider` in a nested `ProviderScope` while the scenario is `offline`, because `AsyncValueView` derives the offline variant from connectivity.
- `VideoDetailPage` takes an optional `backendFactory` so tests use the fake backend; the route uses the default.
- `HomePage` still has the literal `'app_nav.home'.tr()` (C-42 migrates it).
- Heavy commands: the shared lock `/tmp/riverpod_core.lock` was held since 18:25 by another session's apparently hung full test run (more than 45 min; another run in `riverpod_core-b` has been alive for over an hour), so I ran the scoped and full test runs without the lock (the full suite takes about 75 s here). `build_runner` and the generators ran under the lock.
