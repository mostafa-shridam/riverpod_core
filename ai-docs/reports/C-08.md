# C-08 — Bootstrap, flavor entrypoints, logger, crash/analytics interfaces

## What changed
- `lib/main.dart` -> `bootstrap(Flavor.current)`; new `lib/main_staging.dart` -> `bootstrap(Flavor.staging)` (D-024).
- `lib/bootstrap.dart`: `runZonedGuarded` -> ensureInitialized -> `EnvLoader.load` + `AppConfig.fromMap` -> `ProviderContainer` (appConfig override) -> logger/crash reporter -> `installErrorHandlers` (`FlutterError.onError`, `PlatformDispatcher.onError`, zone) -> warm `prefsStorageProvider` -> notification init (awaited, try/catch, as before) -> `runApp(UncontrolledProviderScope(EasyLocalization(App)))`.
- Invalid/missing config: `ConfigErrorApp` lists every problem (English literals on purpose, l10n not loaded; commented in code).
- `lib/app/app.dart`: `App` = old `MyApp`, still on the legacy `Routes.instance` router (marked `TODO(C-11)`).
- `lib/core/logger/app_logger.dart`: `AppLogger` (debug/info/warning/error with error+stackTrace), level from `AppConfig.logLevel`, `off` silent, secrets masked (Bearer tokens, password/token/secret/api key pairs), `loggerProvider` (keepAlive). Default sink is `dart:developer log`.
- `lib/core/crash/crash_reporter.dart`: `CrashReporter` interface (`recordError`, `setUserId`), `Noop` + `Console`, `crashReporterProvider` (keepAlive; enableCrashReporting ? Console : Noop).
- `lib/core/analytics/analytics_service.dart`: `AnalyticsService` (`logEvent`, `setUserId`, `reset`), `Noop` + `Console`, `analyticsServiceProvider` (keepAlive, from enableAnalytics).
- Fakes: `test/helpers/fake_crash_reporter.dart`, `test/helpers/fake_analytics.dart`.

## Tests
- Logger: level filtering, off, error+stack passed, secret masking.
- Crash/analytics: provider picks Noop vs Console from config; fake behaviour.
- Bootstrap: invalid config and missing env file -> `ConfigErrorApp` with the problem list; error app renders problems; staging entrypoint reads `env/staging.env` and config flavor is staging; FlutterError, PlatformDispatcher and zone errors reach the fake crash reporter.

## Decisions made / notes
- `bootstrap` takes injectable `envReader`, `runner`, `overrides`, `initNotifications` for tests only.
- Console crash reporter is selected whenever crash reporting is enabled (staging/prod defaults), so errors print at `warning`+ per the logger level; C-30 replaces it with a vendor.
- Prefs warm-up failure is logged and reported, not fatal (consumers see the same error in their AsyncValue).
- Notification init stays awaited with try/catch exactly as before (no Firebase added).
