# C-37 — Config from dotenv, automatic flavor

Worker E · branch `worker-e`

## What changed
- `Flavor.current` = `kReleaseMode ? prod : dev`, via the pure `Flavor.resolve({isRelease})` (testable). Staging stays explicit (`main_staging.dart`, C-08).
- New `EnvLoader.load(Flavor, {AssetReader? reader})` loads the bundled asset `env/<flavor>.env`, parses it with `flutter_dotenv` (`DotEnv().loadFromString`) and returns a `Map<String,String>`. Missing file or no values throws `ConfigException` ("Copy env/dev.env.example to env/dev.env ..."). The reader is injectable; the default is `rootBundle.loadString`.
- `AppConfig.fromMap(Flavor flavor, Map<String,String> env)`. Removed `fromEnvironment()`, `ensureFlavor` and the `FLAVOR` key/parsing.
- `ConfigException` message no longer shows the dart-define command; it now says to fix `env/<flavor>.env` (copy the `.example`).
- `env/*.example.json` deleted; `env/{dev,staging,prod}.env.example` added (placeholders only, no FLAVOR key). `.gitignore`: `env/*.env`, `!env/*.env.example`.
- `pubspec.yaml`: `flutter_dotenv: ^6.0.0` and the asset declaration (see Decisions). `pubspec.lock` updated.
- Only `lib/core/config/env_loader.dart` imports dotenv in `lib/`.

## Decisions made or needed
- Asset declaration deviates from the literal task text. Declaring the three `env/*.env` files makes `flutter test`, `flutter build` and `flutter analyze` (warning `asset_does_not_exist`) fail on a fresh clone, because the real files are ignored. I declared the folder `- env/` instead. It always exists (the examples are committed), so a fresh clone builds and tests; a missing real file then surfaces as the `EnvLoader` `ConfigException` at startup. Side effect: `*.env.example` files (placeholders) are bundled too, harmless. Lead to confirm, or choose another strategy.
- `config_exception.dart` is not in the task's Files list; I changed only its message text because it named the removed dart-define command (it would otherwise be false). Tell me if that must be reverted.
- Tests inject maps/readers; no real `.env` files are needed.
- Stale references left for their owners (not edited, outside Files): `ai-docs/CHECKLIST.md` line 12 and C-02/C-13 task text mention dart-define / `env/*.example.json`; `ai-docs/HOW_TO_START_A_NEW_APP.md` step.
