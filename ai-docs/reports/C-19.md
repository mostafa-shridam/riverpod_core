# C-19 — Screen security: biometric lock and screenshot blocking (D-041)

Worker S5, branch `worker-w`.

## What changed
- `core/security/biometric_service.dart`: `BiometricBackend` seam, `LocalAuthBackend` (the only file importing `local_auth`), `BiometricService` (`isAvailable`, `authenticate(reasonKey)`), typed `BiometricResult { success, cancelled, failed, notAvailable, lockedOut }`, `mapLocalAuthCode` (every `LocalAuthExceptionCode` mapped, test checks all values are covered). Failures are results, never exceptions.
- `core/security/app_lock_controller.dart`: keepAlive `AppLockController` (freezed `AppLockState`: enabled, locked, obscured, unlocking, lastResult). Flag stored in prefs through the generic string-list slot (`settings.appLock`, `['1']` = on; a device setting, so it survives logout). Locks at cold start when on and when the app returns after `appLockTimeoutProvider` (default 30 s, override per app; zero = every return). Timer starts at the first step away (inactive/hidden/paused). `appLockClockProvider` for tests. Enabling requires one successful authentication. Unlock = `local_auth` with device-credential fallback (`biometricOnly: false`).
- `core/security/secure_screen.dart`: own MethodChannel `riverpod_core/secure_screen` (`setSecure(bool)`), no-op on unsupported platforms, on missing handler and on platform errors. `SecureScreenGate` ref-counts holders; `SecureScreen` widget holds it while mounted. App lock itself holds it while enabled (so the app is also hidden in the Android recents).
- `core/security/app_lock_overlay.dart`: `AppLockOverlay` Stack over the app (not a route), mounted in `MaterialApp.builder`; covers content in the app switcher (obscured) and when locked, excludes the covered content from focus and semantics, auto-prompts when it becomes locked, button retries.
- `core/design_system/widgets/security/app_lock_screen.dart`: presentational lock screen (reuses `EmptyState`), exported from the widgets barrel.
- `features/more/presentation/pages/security_settings_page.dart` (`/security-settings`): `AsyncValueView` over device availability (loading skeleton, error + retry, success), `AppSwitch`; disabled with an explanation when unavailable; snackbar for cancelled/failed/locked-out.
- Native: Android `MainActivity.kt` now extends `FlutterFragmentActivity` (required by local_auth), `FLAG_SECURE` channel; `AndroidManifest.xml` `USE_BIOMETRIC`; both `styles.xml` LaunchTheme parents changed to `Theme.AppCompat.*.NoActionBar` (required by local_auth for Android 8 and below). iOS `AppDelegate.swift` channel + cover view on `willResignActive`; `Info.plist` `NSFaceIDUsageDescription` (neutral English string).
- Translations: new `security.*` group (ar + en), generated files regenerated and committed.

## Decisions made or needed
- Prefs: no generic bool API exists, and `storage/**` is owned by C-41, so the flag uses the existing `getStringList/setStringList` slot. Follow-up: a typed `appLockEnabled` getter once C-41 is merged.
- If the device loses all credentials while the lock is on, `unlock()` returns `notAvailable`, turns the lock off and persists it (otherwise the user is locked out forever).
- Disabling needs no authentication (spec silent; whoever sees the switch is already past the lock).
- Screenshot blocking while the lock is on is app-wide on Android (`FLAG_SECURE`), which is also what hides the recents thumbnail. iOS cannot block screenshots; it covers the window in the switcher only.
- `AsyncValueView` shows its offline banner on the settings page when offline although the device check is local; acceptable, not worked around.
