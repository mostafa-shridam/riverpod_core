# C-15 — Upload and download with progress and cancel

Worker L · branch `worker-l`

## What changed
- `UploadService.upload({path, files, fields, onProgress, cancelToken})`: multipart POST through `dioProvider`. Returns `UploadResult(statusCode, data)`.
- `DownloadService.download(url, fileName, {onProgress, cancelToken})`: writes `<name>.part` in the transfer directory and renames it on success. The `.part` file is deleted on cancel and on any failure. No resume. Only the last path segment of `fileName` is used, so a name cannot escape the directory.
- `transferDirectoryProvider` (keepAlive) holds the directory factory. Default: `getApplicationCacheDirectory`. Tests override it with a temp directory.
- `TransferController` (`@riverpod`, autoDispose) with state `TransferIdle | TransferRunning(progress) | TransferDone(result) | TransferFailed(AppException) | TransferCancelled`. Actions: `upload`, `download`, `cancel`, `reset`. Starting while running is ignored. Dispose cancels a running transfer. Results that arrive after `cancel()` or dispose are dropped.
- `ProgressStream` gives progress as `Stream<double>` (pass `report` as `onProgress`). `progressFraction` clamps to 0..1 and returns 0 when the total is unknown.
- All errors go through `mapError`; a cancel becomes `CancelledException`.

## Tests added (15)
- Upload: multipart fields, file name and content type, progress ends at 1.0; server error maps to `ServerException`; cancelled token gives `CancelledException`.
- Download: progress emission and `.part` renamed on success; cancel mid-transfer leaves no file; 404 gives `NotFoundException` with no file; socket failure gives `NetworkException`; unsafe name stays in the directory; `progressFraction`.
- Controller: idle, running progress 0, 0.5, 1.0, then done with the file; upload done; failure gives `TransferFailed(ForbiddenException)`; `cancel()` mid-transfer gives cancelled and removes the file; `cancel()` while idle is a no-op; `reset()`.

## Decisions made or needed
- The callback type is `TransferProgressCallback` because dio already exports `ProgressCallback`.
- The test adapter is a local `TransferAdapter` (in the transfer test folder), because `FakeHttpAdapter` cannot stream a response in chunks or read the request body. `test/helpers` was not touched (outside the Files list).
- `TransferDone.result` is typed `Object` (an `UploadResult` or a `File`) to keep one non-generic controller.
- Needs a decision: none blocking.

## Suggested follow-ups
- Retry interplay: a multipart POST carries an `Idempotency-Key`, so `RetryBackoffInterceptor` may retry it on a transient error, but a `FormData` can be finalized only once, so the retry would fail. Fix in the interceptor task: skip retry for `FormData` bodies (or add an opt-out in `extra`).
- A shared progress widget in the design system (not in this task).
