## Decisions made or needed
- Toasts are drawn by our own overlay queue, not `ScaffoldMessenger.showSnackBar`, because the native snackbar cannot go to the top. The `ScaffoldMessenger` key is used to find the root `Overlay` (walk down from the messenger element) when no `BuildContext` is given. Context-based calls pass the context as a hint. NEEDED: `lib/app/app.dart`/`main.dart` must pass `ref.watch(appMessengerProvider).key` as `scaffoldMessengerKey` (not my file; follow-up).
- `showAppSnackbar`/`showAppToast` read the messenger with `ProviderScope.containerOf(context)`, so a `ProviderScope` above is required (always true in the app).
- Toast display time is not a token. It is derived: `durations.slow * 10` (x15 with an action). Follow-up: add a `toast` duration token if the owner wants it tunable.
- Each toast gets a fresh `GlobalKey`; reusing one key revived the previous (closing) State in the same frame, found by the queue test.
- Status icon dialogs center icon and text; dialogs without an icon use start alignment (my reading of "centered-start aligned").
- `AppProgressBar` percent uses `intl` `NumberFormat.percentPattern(locale)` directly because `core/l10n` formatters do not exist yet.
- `AppFormSheet` is a static `show` holder (no widget class to instantiate) because the footer needs the sheet's own context.
- Own enum `AppStatusType` shared by alerts/toasts/banners; the legacy `lib/core/enum/alert_type.dart` is now unused (not in my Files, left alone).
- Controls inside overlays use raw `FilledButton`/`TextButton`/`IconButton` styled via the theme, because C-09's `AppButton` does not exist yet. Follow-up: switch to `AppButton` once merged.
