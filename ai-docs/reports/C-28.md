# C-28 — Release scripts and signing from untracked files

## What changed
- `android/app/build.gradle.kts`: reads `android/key.properties` (if present) into a `release` signing config. The release build type uses it; otherwise it points at the debug config only as a placeholder, and a `gradle.taskGraph.whenReady` check throws `GradleException("Release build requires android/key.properties (not found). ...")` when any `assemble|bundle|package…Release` task of the app is in the graph. Debug/profile builds and `flutter run` never need the file.
- `tool/release/build_android.sh`, `build_ios.sh` (executable, `set -euo pipefail`): `--flavor staging|prod` (default prod; entrypoint `lib/main_staging.dart` / `lib/main.dart`), check `env/<flavor>.env` and the signing file, run the gate (`dart format`, `analyze`, `test`), then `flutter build appbundle|ipa --release --obfuscate --split-debug-info=build-symbols/<platform>` (`ipa` adds `--export-options-plist=ios/ExportOptions.plist`), print the artifact path. No secrets echoed.
- `tool/release/README.md`: keytool command, `key.properties` fields, where to keep files, iOS export options, symbols.
- `android/key.properties.example`, `ios/ExportOptions.plist.example` (plutil lint OK), `.gitignore` additions.

`tool/release/build_android.sh`, `tool/release/build_ios.sh`, `tool/release/README.md`, `android/app/build.gradle.kts`, `android/key.properties.example`, `ios/ExportOptions.plist.example`, `.gitignore`, `ai-docs/TASKS.md`, this report.

## Tests / verification
- `bash -n` on both scripts: OK. `--flavor bogus` exits 2 with a clear message. `shellcheck` not installed: not run. Scripts were not executed end-to-end (the full gate plus signing needs real keys).
- `flutter build apk --release` WITHOUT key.properties, run with `--android-skip-build-dependency-validation` (see blocker below): fails with the intended message:
  `Release build requires android/key.properties (not found). Copy android/key.properties.example to android/key.properties and fill it in; see tool/release/README.md. Release builds are never signed with the debug key.`
- Without that flag the build fails earlier, before my code, at line 1 of `build.gradle.kts`: `Your project's Gradle version (8.13.0) is lower than Flutter's minimum supported version of 8.14.0`.
- A successful signed release build and a successful debug APK were NOT achieved in this sandbox: `flutter build apk --debug` (with the same flag) fails in `:firebase_auth:compileDebugKotlin` ("Module was compiled with an incompatible version of Kotlin. 2.4.0, expected 2.2.0"), also in a part of the project this task does not own. The Gradle script itself configured fine in both runs (the failure came after configuration), but I cannot claim debug builds work end to end. No keystore was created, so signed-release success is unverified.
- Gate: `dart format --set-exit-if-changed lib test tool` clean, `flutter analyze` 0 issues, `flutter test` 656 green.

## Decisions made or needed
- Release detection uses task names matching `^(assemble|bundle|package)(.*)Release$` in the app project. `storeFile` resolves relative to `android/` (or absolute).
- NEEDS A TASK (blocker for real builds, not in my Files list): Gradle wrapper is 8.13 (Flutter needs >= 8.14), Kotlin Gradle plugin is too old for the plugin dependencies (firebase_auth needs metadata 2.4.0, project has 2.2.0), `compileSdk` 36 but `permission_handler_android` wants 37. Likely owned by the native/flavors task (C-31) or a dedicated toolchain upgrade; please assign.
