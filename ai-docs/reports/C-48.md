## Flaky test: `cancel() mid-transfer gives cancelled and removes the file`
Cause: after adding the first chunk the test waited a fixed `Future.delayed(20 ms)` and assumed Dio had received and written the chunk (part file created) by then. Under CPU load the chunk could still be in flight when `cancel()` ran, so the cleanup race left the file state timing-dependent.
Fix: a `Completer` gate completed by the controller's own state listener when `TransferRunning(progress == 0.5)` is reported (that callback fires only after the chunk was received). No sleep, no timeout. The assertions are unchanged; the test still proves cancel gives `TransferCancelled` and leaves the directory empty. Verified: 10 runs of the file under 12 busy-loop processes, all green; full suite green.
