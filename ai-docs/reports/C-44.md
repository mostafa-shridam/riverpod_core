# C-44 — Cache-first policy, retention and pruning (D-038)

Status: REVIEW. Worker B, branch `worker-b`. Merged with `main` (C-41 PASS, C-44 READY at `26dbac1`).

## What changed

- **Presets** (`lib/core/storage/cache/cache_policy.dart`). `CachePolicy` with `short` (5 min fresh, 1 day kept), `medium` (1 h, 7 days; the default), `long` (1 day, 30 days) and `static` (7 days, 90 days). `defaultMaxAge` is gone; nothing else uses a hand-written ttl.
- **One call for repositories** (`cached_repository_helper.dart`). `load<T>(key, fetch, decode, encode, policy, fresh)` returns the data as a `Future`.
  - Cache-first by default: the cached value comes back at once. The revalidation finishes in the background, and the next read is fresh.
  - `fresh: true` (refresh, reload) awaits the network directly and rethrows the mapped error, even when a cached copy exists.
  - `watch<T>` (the stream form) is unchanged in shape. It now takes a `CachePolicy` and a fetch that receives the stored ETag.
- **ETag round trip.** `CacheFetch<T>` is `({T? value, String? etag})`; a null value means 304. The helper passes the stored ETag to `fetch`. `HttpRemoteConfigSource` sends `If-None-Match` and treats 304 as unchanged.
- **Unchanged data.** A 304, or an identical encoded payload, keeps the stored copy and only moves its retention fields (`CacheStore.revalidate`). A stale copy that is confirmed unchanged gets one emission to clear its stale flag. A changed payload is written once and emitted once.
- **Retention** (`lib/core/storage/cache/cache_pruner.dart`). `CachePruner.prune()` removes entries past their own `maxAge` (`CacheStore.deleteExpired`), then the least recently accessed entries above a 500-entry cap.
- **Scheduling** (`lib/core/storage/cache/cache_prune_scheduler.dart`). `CachePruneScheduler` prunes after the first frame and on resume when the last prune (kept in `PrefsStorage.lastCachePrune`) is more than 24 h old. Bootstrap starts it with one line.
- **Features.**
  - Remote config (`remote_config_repository.dart`) uses `CachePolicy.short` in place of the 1 h constant.
  - Videos (`videos_repository.dart`) `fetchFeed({fresh})` is one `load` call on the `short` preset.
  - The videos controller passes `fresh: true` from `refresh()` and `reload()`. Its initial load and search stay cache-first.
  - The feature template (`.fttemplates/feature`) follows the same pattern: `fetchItems({fresh})` via `load`, `refresh()` with `fresh: true`, and test support that overrides the cache helper. A sample feature generated from it analyzes clean and its 22 tests pass.
- **Docs.** `ai-docs/STATE_AND_DATA.md` caching section rewritten for presets, `load`, `fresh`, ETag and pruning.

## Decisions

- **Refresh is network-first.** Pull-to-refresh and reload wait for the network (approved as option A by the Lead). The initial load and search are cache-first.
- **Unchanged + stale emits once.** D-038 says an unchanged payload does not re-emit. A stale copy that is confirmed still needs its stale flag cleared, so it emits once with the same data. Only that case emits.
- **No-op check compares the encoded payload.** D-038 names a payload hash. Comparing strings gives the same result without an extra field; a hash can be added if payloads get large.
- **Cap is an entry count (500),** not bytes. `CachePruner.defaultMaxEntries` is the one place to change it.
- **Remote config uses `short`.** A force update has to reach users within minutes.
- **Videos feed uses `short`.** Feeds change often.
