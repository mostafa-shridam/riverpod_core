## Decisions
- Needed (for the Lead): scheme is `riverpod-core`, not `riverpod_core`. The task text says `riverpod_core://videos/abc`, but `Uri.parse('riverpod_core://x')` throws "Illegal scheme character", so Flutter/go_router could never read such a link on a device. The registered scheme is the package with `_` as `-`; `routeForAppLink` still maps the underscore spelling, so the stated test case holds. Please confirm or amend the doc/task wording.
- **D-044 (text for DECISIONS.md)** — Native splash and launcher icons via `flutter_native_splash` and `flutter_launcher_icons`.
  - Decision: `flutter_native_splash` 2.4.8 (MIT, dev dependency only; adds the transitive dev packages `ansicolor` 2.0.3 and `universal_io` 2.3.1) generates the native splash for Android (incl. Android 12) and iOS, light and dark, from a config block in `pubspec.yaml`. `flutter_launcher_icons` 0.14.4 (MIT, already a dev dependency) generates the launcher icons. Both run only on demand (`dart run flutter_native_splash:create`, `dart run flutter_launcher_icons`) and their output is committed, so a clean clone builds without running them. The splash color is the `brandSeedColor` hex (guard test keeps them equal); the splash image is the adaptive-icon foreground.
  - Why: the native splash cannot be written in Dart; hand-writing the per-density, night and v31 files is error prone. Dev-only, no runtime code.
  - Alternatives: hand-written native files (rejected: many files, easy to get wrong); `flutter_native_splash` only for Android (rejected: iOS launch screen needs the same).
  - Trade-off: the tools re-indent `Info.plist` and flutter_launcher_icons rewrites `ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS` in `project.pbxproj`; both were reverted here and the docs tell apps to do the same.
- Versions: flutter_native_splash 2.4.8 (MIT), flutter_launcher_icons 0.14.4 (MIT).
