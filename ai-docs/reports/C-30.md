# C-30 — Crashlytics and Firebase Analytics, optional (D-042)

Worker S6, branch `worker-x`.

## What changed
- `core/firebase/`: `FirebaseBootstrap.ensureInitialized()` (init once, never throws, logs "Firebase not configured: crash/analytics disabled" once), `firebaseAvailableProvider`, `initObservability(container)` (the single bootstrap call), `collectionConsentProvider` (persisted on/off, applied to both vendors; default ON via `defaultCollectionConsent`).
- `core/crash/`: `CrashReporter` gained `setCustomKey`, `log` (breadcrumb), `setCollectionEnabled`. New `FirebaseCrashReporter` over a `CrashBackend` seam (`CrashlyticsBackend` is the only file importing `firebase_crashlytics`). `crashReporterProvider`: Firebase impl only when `ENABLE_CRASH_REPORTING` AND Firebase available, else Noop (Console is no longer auto-selected).
- `core/analytics/`: `AnalyticsService` gained `logScreenView`, `setUserProperty`, `setCollectionEnabled`. New `FirebaseAnalyticsService` over an `AnalyticsBackend` seam; params cleaned (nulls dropped, bool to 1/0, other to string). `AnalyticsRouteObserver` + `analyticsRouteObserverProvider`.
- `core/bootstrap/bootstrap.dart`: 2 lines (import + `await initObservability(container)` before the crash reporter is read). Error handlers already routed fatal/non-fatal through `CrashReporter`; unchanged.
- `core/auth/session_controller.dart`: opaque user id set on sign-in and restore, cleared on logout (crash + analytics), best effort.
- `core/notifications`: `FirebasePushBackend` now takes `ensureFirebase` from `FirebaseBootstrap` (provider wiring in `notification_providers.dart`), so Firebase initializes exactly once.
- Native: `android/settings.gradle.kts` declares the google-services (4.5.0) and crashlytics (3.0.8) Gradle plugins `apply false`; `android/app/build.gradle.kts` applies them only if `android/app/google-services.json` exists. iOS `project.pbxproj`: optional "Crashlytics symbol upload" phase, skipped without `GoogleService-Info.plist`, without dSYM, or without the pod. `.gitignore` now ignores `google-services.json` and `GoogleService-Info.plist` (they were NOT ignored before).
- `ai-docs/FIREBASE.md` (new).
- Config flags: the existing `ENABLE_CRASH_REPORTING` / `ENABLE_ANALYTICS` (on for prod/staging, off for dev) already matched the requirement; I kept those names instead of adding `CRASH_REPORTING` / `ANALYTICS`.
