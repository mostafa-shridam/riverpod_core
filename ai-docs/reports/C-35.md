## Gating (exactly)
`ShowcasePage.isEnabled(flavor)` is `flavor != Flavor.prod`. Two places use it:
1. `ShowcaseRoute.redirect` reads `appConfigProvider.flavor` (via `ProviderScope.containerOf(context)`); in prod it redirects to `HomePage.routeName`, so a deep link to `/showcase` in a release build lands on home.
2. `HomePage` watches `appConfigProvider.select(flavor)` and renders the "Component gallery" `AppListTile` (key `open-showcase`, pushes `ShowcaseRoute`) only when enabled.
The route class still exists in prod builds (typed routes are static); it is unreachable because of the redirect. Nothing else imports the showcase feature except `routes.dart` and `home_page.dart`.

## Decisions made / deviations
- Theme toggle is page-local (`Theme` wrapper with `buildLightTheme/buildDarkTheme`): the app has no global theme controller and a gallery must not change app settings. Overlays opened from the page inherit it because Flutter captures the caller's themes.
- Text scale override applies only after the slider is touched and only to the list (not the controls), so the system scale is never replaced silently (CONVENTIONS "never fixed textScaler" is respected outside this explicit developer tool).
- Data-state picker is an `AppChipGroup` instead of a segmented control: eight segments do not fit a phone at 2.0x; chips wrap.
- The "offline" state is simulated by overriding `connectivityProvider` in a nested `ProviderScope` around the demo only.
- The HLS player is mounted on a button press so opening the page does not start two network streams; the page list is a lazy `ListView`.
- Sample URLs are duplicated in `showcase_samples.dart` (not imported from `features/videos`: a feature never imports another feature, D-028 allows deleting either).
- Route literal: pages own `routeName` (D-036), so no `paths.dart` edit was needed.
- Tests must avoid `pumpAndSettle` on this page because loading buttons spin forever; they use `settle()` (two pumps). `cached_network_image` needs platform channels, so the broken-URL rendering is covered by `app_image_test`, and here only the demo wiring is asserted.
- `AppBottomNavBar` is not shown (it is the app shell's navigation and turns into a rail on tablets).
- The `lock` directory `/tmp/riverpod_core.lock` was held for over an hour by hung flutter_tester processes of other worktrees, so the final targeted and full test runs were done without waiting for it.
