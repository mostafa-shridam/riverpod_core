# C-18 — Onboarding and splash pages

Worker A · branch `worker-a` · worktree `../riverpod_core-a`

## What changed
- **Startup sequence** (`lib/core/startup/startup_controller.dart`, keepAlive `AsyncNotifier<void>`): runs the session restore, then the settings read (which carries the onboarding-seen flag), then waits for the minimum display time. Config is already validated in bootstrap. Remote flags are not built here; the comment marks where they join.
  - Minimum display time is the provider `splashMinimumDisplay` (800 ms). Tests override it with zero.
  - A failed step leaves the controller in error. Retry is `ref.invalidate(startupControllerProvider)`.
  - `startupReady` (keepAlive `bool`) is true once the sequence has finished. The router waits for it.
- **Redirect** (`lib/core/router/guards/app_redirect.dart`): new parameter `startupReady` (default `true`, so existing rules are unchanged). While it is false, every location except the splash goes to the splash. `app_router.dart` listens to `startupReady` and passes it in.
- **Splash** (`lib/core/startup/splash_page.dart`): now a `ConsumerWidget`. It shows the mark and a spinner while starting, and an `ErrorState` with retry on failure. The postFrame `restore()` call moved into the controller. The mark is still the neutral placeholder, unchanged.
- **Onboarding** (`lib/features/onboarding/**`):
  - `data/onboarding_slides.dart`: three slides, each an icon and two `LocaleKeys`. No image assets.
  - `providers/onboarding_controller.dart`: the current slide index (`select` clamps it), `next()` (finishes on the last slide), and `finish()`, which stores `onboardingSeen` and invalidates `prefsStorageProvider` so the router leaves onboarding.
  - `presentation/pages/onboarding_page.dart`: replaces the C-11 stub. `PageView` synced with the controller; Skip (hidden on the last slide, with the same row height kept) and Next / Get started. Save failures show an error snackbar.
  - `presentation/widgets/onboarding_slide_view.dart`: icon in a tinted circle sized from tokens, then title and body.
  - `presentation/widgets/onboarding_dots.dart`: page indicator, a `Row` so it mirrors in RTL. Its semantics label is "Page n of m".
- **Translations**: top-level `onboarding` in `en.json` and `ar.json` (skip, next, getStarted, pageOf, three slides with title and body).
- **Generated**: `lib/generated/*` regenerated (D-037), build_runner run for the new `.g.dart` files.
- **Placeholder**: `lib/core/router/placeholder_pages.dart` no longer exists (removed earlier), so nothing was deleted here. The onboarding stub it would have held is replaced by the real page.

## Decisions
- **Startup readiness is a router input, not a splash widget rule.** The router already decides where to go; making the minimum display time part of the same redirect means no page can skip it.
- **Minimum display time is a provider, not a constant.** Tests set it to zero; the production value is 800 ms.
- **Retry through `invalidate`, not a second method.** The notifier's `build` is the sequence, so a retry is a rebuild.
- **Flag write invalidates `prefsStorageProvider`**, as the C-11 stub did, so the `onboardingSeen` provider re-reads the flag.
- **D-038 (cache-first)**: the only reads are the secure store and local preferences; there is no network read, so there is no cache policy to apply here.

## Known limitations
- Golden PNGs use the test font, which has no English or Arabic glyphs, so the text shows as placeholder boxes. The layout is what the goldens check. Same limitation as the auth goldens (C-17).
- The 8-state set applies to the splash only (loading, error with retry, success is the redirect). The onboarding carousel is a static success state.
- Text scaling and tablet layouts are not covered by a test in this task. The page uses design-system tokens and `ErrorState`, but I did not add a scale or tablet case.
