# C-47 — Notification channels localized after translations are loaded

## What changed
- Root cause: `bootstrap` awaits `notificationServiceProvider.initialize()` before `runner(EasyLocalization(...))`. `initialize()` called `syncChannelLabels()`, which resolves `LocaleKeys.notifications_*` with `.tr()` while no translations were loaded, so easy_localization logged `Localization key [...] not found` and Android channels/groups would have been created with raw key strings as names.
- Fix: `NotificationService._initialize` no longer creates channels. New widget `NotificationLabelSync` (`lib/core/notifications/notification_label_sync.dart`), mounted in `App`'s `MaterialApp.builder`, runs after the first frame (translations loaded) and whenever `context.locale` changes: `await initialize()` (idempotent, never throws) then `syncChannelLabels()`. Same channel ids, so Android renames by re-creating. Non-blocking (`unawaited` post-frame). Sign-in and permission-granted paths still call `syncChannelLabels()` (translations are loaded by then).
- `bootstrap.dart` is NOT touched: the early `initialize()` call stays (timezone, local plugin, push, cold-start tap) and just no longer localizes anything.

## Files
- `lib/core/notifications/notification_label_sync.dart` (new), `lib/core/notifications/notification_service.dart`, `lib/core/app/app.dart` (one wrapper line + import)
- `test/core/notifications/notification_label_sync_test.dart` (new), `test/core/notifications/notification_service_test.dart`

## Tests
- New: channels are created after `initialize` (recorded order), with real translated names, and no key resolves to itself; language switch to `ar` re-registers the same channel ids with different names; `initialize()` alone registers no channels.
- Changed (behaviour, not weakened): `initialize` test used to assert `createChannelsCalls > 0` and 4 channels right after `initialize()`. That is no longer true by design (channels are created by `NotificationLabelSync` after translations load); it now asserts 0 calls, and channel creation is covered by the new widget test.
