# C-03 report — AppException, error mapper, localized messages

## What changed
- Sealed `AppException` hierarchy (`message`, `cause`, `stackTrace`): Network, RequestTimeout, Unauthorized, Forbidden, NotFound, Validation(`fieldErrors`, `firstMessageFor`), Server(`statusCode`), Cancelled, Unknown. All use named optional args.
- `mapError(error, stack, {parser})` implements the NETWORKING.md table; nested/direct `AppException` returned as is; `SocketException`, `dart:async` `TimeoutException` handled; anything else is `UnknownException`.
- `ErrorBodyParser` (interface) + `DefaultErrorBodyParser` (`{message, errors:{field:[..]}}`, JSON string or map, garbage → empty result, never throws).
- `errorMessageKey` (exhaustive switch), `errorRetryKey`, `errorServerMessage`.
- `errors.*` keys (network, timeout, unauthorized, forbidden, notFound, validation, server, cancelled, unknown, retry) in ar and en as a final top-level `errors` object; `LocaleKeys`/`codegen_loader` regenerated.

## Files
`lib/core/errors/{app_exception,error_mapper,error_messages}.dart`, `assets/translations/{ar,en}.json`, `lib/generated/{codegen_loader,locale_keys}.g.dart`, `test/core/errors/{error_mapper,error_messages}_test.dart`.

## Tests
Every mapping row (using `FakeHttpAdapter` through real Dio), passthrough, parser variants, custom parser, exhaustive keys, all keys non-empty in both languages.

## Decisions made (please confirm)
1. Server message is NOT user-safe by default: `DefaultErrorBodyParser(trustServerMessage: false)`. Docs say "when the parser marks it user-safe" but not the default. `ValidationException`/`ServerException` carry `userMessage` (null unless marked safe); `errorServerMessage` exposes it.
2. 400/409/422 without field errors map to `UnknownException` (table only defines the with-fields case).
3. `DioExceptionType.transformTimeout` maps to `RequestTimeoutException`; `badCertificate` to `UnknownException`.
4. `ErrorBodyParser`/`ParsedErrorBody` live in `error_mapper.dart` (no extra file allowed by the task list).
